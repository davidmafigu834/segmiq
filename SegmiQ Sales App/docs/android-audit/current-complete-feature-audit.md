# SegmiQ Sales Android — current feature completion audit

Audit date: 2026-10-31. Source of truth: Android tree at commit `7e743eb43fd2995636c8b2f7133d606a1d2c3cb6`, plus the backend routes in this repository. This is not a restatement of the older phase reports.

## How status was decided

A screen, button, DTO or repository method is not enough for COMPLETE. A feature is COMPLETE only when the signed-in path performs the real action inside its intended scope.

Verification labels:

- **SRC** — Kotlin, manifest, and matching backend route read on 2026-10-31.
- **JVM** — `testDebugUnitTest`: 18 suites, 129 tests, 0 failures, 0 skipped.
- **EMU** — debug APK on emulator `emulator-5554` (`sdk_gphone_x86_64`, window 720×1184). Login, empty-credential validation, and the local demo were exercised. No production sign-in. No production writes.
- **NO-PROD** — the live authenticated screen was not opened against www.segmiq.com in this pass.

The app’s production base URL is `https://www.segmiq.com` (`app/build.gradle.kts`). Real-estate reads are additionally pinned in `acceptedEstateReleases` to origin `https://www.segmiq.com:443`, contract 1, revision `7e743eb…`, role `SALESPERSON`, and a read-only resource set. Writes, compliance, and private image hosts are absent from that acceptance record. Backend feature flags can still say writes are enabled; Android will refuse them until the acceptance record changes.

`LiveModule.*.implemented` is stale for several real-estate modules. Those modules are routed in `LiveSalesApp` through `EstateServerScreen` when `EstateAccess.reason()` is null. The More-menu subtitle still says “Continue on SegmiQ web” because it trusts the `implemented` flag.

They were not clicked against production. The emulator pass is limited to the screenshots in `docs/android-audit/screenshots/current-2026-10-31/`.
