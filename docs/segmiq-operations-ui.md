# SegmiQ operations UI

Short reference so delivery screens stay one product.

## Layout
Workbench. Customer name, then the job, then the stage, then the next step. Metadata sits under that, not in a grid of equal cards.

## Project workspace
Overview, Work, Commercial, Delivery, Assets, Files, History.

Work holds tasks and visits. Commercial holds payments and equipment. Delivery holds installation, QA, commissioning, and handover. Sales context stays on Overview.

## Status
Use the existing stage labels: Planning, Site Assessment, Awaiting Customer, Ready to Schedule, Scheduled, In Progress, Quality Check, Handover, Completed. Colour does not carry the state. The milestone mark does.

## Attention
One list. Deposit, stock, overdue assessment, QA rework, and handover come from the project record. Do not repeat the same gap in the header, a banner, and a metric.

## Forms
Create and schedule actions stay in the existing drawers. Assessment uses one section at a time, with Save draft and Continue fixed at the bottom. Payment confirmation names the amount before it posts. Field flows keep Save and Continue within reach.

## Portal
Customer pages use the same type, paper, and lime accent as the company app. Stage is a word. Current progress uses the lime mark. Bottom navigation is Home, Projects, System, Files, Support. No internal status codes.

## AI
Ask SegmiQ sits beside the record. Answers show the result, the sources, and an approval card before a write. It does not replace the next-step control.

## Responsive
Lists become stacked rows below the `md` breakpoint. Section navigation wraps. Touch targets stay at least 44px.
